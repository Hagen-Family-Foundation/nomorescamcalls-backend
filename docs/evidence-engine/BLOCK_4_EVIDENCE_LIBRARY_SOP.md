# Block 4 — Evidence Delivery SOP

## Purpose

Block 4 delivers the completed evidence package from Block 3 to the Evidence Library.

Block 4 performs no other work.

---

## Trigger

Block 4 begins when it receives the completed evidence package from Block 3.

At this point:

- the live call has ended or has been connected
- the recording has ended
- all deductions have been applied
- the final standing has been calculated
- the completed evidence package is ready for delivery

---

## Input

Block 4 receives the completed evidence package from Block 3.

The package contains:

- Telnyx information
- OpenAI information
- IPQS information
- deductions
- final standing
- call result
- recording reference
- recording completion information

Block 4 does not inspect, change, separate, rename, interpret, or reorganize the contents.

---

## Standard Operating Procedure

1. Receive the completed evidence package from Block 3.
2. Deliver the complete package to the Evidence Library.
3. Record whether delivery succeeded or failed.

---

## Evidence Library

The Evidence Library receives the completed package.

The Evidence Library performs its own:

- sorting
- placement
- storage
- indexing

Block 4 does not participate in those operations.

---

## Boundaries

Block 4 does not:

- participate in the live call
- start or stop recording
- work with Telnyx
- work with OpenAI
- request IPQS
- apply deductions
- recover deductions
- calculate standing
- connect the call
- divert the call
- inspect evidence
- sort evidence
- rename evidence
- place evidence into library compartments
- interpret evidence

Block 4 only delivers the completed package from Block 3 to the Evidence Library.

---

## Output

Block 4 produces:

- delivery attempted
- delivery timestamp
- delivery success or failure

---

## Error Handling

If delivery fails, Block 4 records the failure.

The completed evidence package remains unchanged and available for another delivery attempt.

---

## Change Control

If implementation and this SOP differ, this SOP is authoritative.

Changes to Block 4 responsibilities require approval before code is changed.
